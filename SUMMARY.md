# link-click-middle-open — Summary

## What changed
- **Middle-click on a post opens it in a new tab.** `FeedPost` Card previously used only `onClick` + `navigate()`, so middle-clicks were ignored. Now handles `onAuxClick` (button 1 => `window.open(..., "_blank")`). External/mention/hashtag links already inside the card call `stopPropagation` on both `click` and `auxclick` so they don't bubble to the card.
- **Plain `https://...` URLs in post content are now links.** `ContentLinks` previously linkified only `#hashtag` and `@mention`. Now also linkifies `https://…` / `http://…` tokens into external `<a target=_blank rel=noopener>` with the same blue/underline styling as hashtags. Trailing sentence punctuation (`.` `,` `)` etc.) handling mirrors `ComposeContent.extractUrl` so "see https://x.com." only links the URL.
- **Link styling fixed.** Hashtags/mentions already had `text-blue-600 dark:text-blue-400 hover:underline`; the missing piece was URLs being plain text at all, plus URLs now use `underline` so they are distinguished from body text. No color regression.

## Why
- Issue 1: middle-clicking a post card should mirror browser expectations for any link-like surface.
- Issue 2: links in post bodies were `text-primary` (same as body) — not visually distinct.
- Issue 3: for `link/news` posts, pasted `https://…` rendered as plain text; clicking did nothing. Verified: `ComposeContent` unfurls a NewsCard only when the backend preview returns, but bodies without a reachable preview (or on PostPage) had no clickable fallback.

## Files touched
- `web/src/components/FeedPost.tsx` — `handlePostClick(event)` handles left vs middle button; Card adds `onAuxClick={handlePostClick}`.
- `web/src/components/ContentLinks.tsx` — adds `URL_TOKEN`, `splitUrlToken()`, renders external `<a>` for URL tokens; adds `onAuxClick(stopPropagation)` to all link types.
- `web/package-lock.json` / build artifacts — regenerated by `npm install` inside worktree to satisfy `tsc -b` for preview build (pinned to local worktree `node_modules`).
